Summary
=======
ECR - Elastic Container Registry
	Where my docker images live
	AWS services (like ECS or Fargate) can pull and run them.
	
		Go to the AWS Console → ECR → Create repository
		Repository name: my-aws-apps
		Visibility: Private
		Leave other defaults → Create repository
		Copy the repository URI, e.g.: 869036203214.dkr.ecr.eu-north-1.amazonaws.com/my-aws-apps
		
ECS - Elastic Container Service
	cloud container orchestrators
	Runs the image
	c.f. Docker Compose = local container orchestrator
	Think of ECS as AWS’s “container manager”.
	Lets you run Docker containers without managing servers
	Handles scheduling, scaling, networking, and monitoring of your containers
	ECS does not run containers - just coordinates everything.
	Uses Fargate to actually run the containers
	Resources - Tasks and Services. c.f. Kubernetes pods
	
	
ECS Cluster
	An ECS cluster is a logical grouping of resources that can run your containerized applications.
	Can run multiple separate applications in a single cluster
	It keeps track of:
		Tasks → single running containers based on a task definition
		Services → long-running or scalable groups of tasks
		Networking (VPC, subnets, security groups)
		You can have multiple clusters for different environments (dev, staging, prod)
	With Fargate	- just a place to keep your services/tasks together
	With EC2		- a group of EC2 machines ready to run your containers
	
	
ECS Task Definition
	A task definition is like a recipe or blueprint for running a container.
	
	It specifies:
		Which container image to use
		How much CPU + memory it needs
		What ports to open
		What environment variables to set
		IAM role, logging, etc.
		You don’t run these directly — you use them to create tasks.
		
		
ECS Task
	A task is a running copy of a task definition.
	
	
ECS Service
	An ECS service is a controller that ensures a certain number of tasks are always running.
	This is the aspect of ECS that is closer to Kubernetes
	e.g.	Keep 3 tasks running at all times.
			If 1 crashes then start another
			
			
ECS example
	Let’s say you want to run a web API.
	Task Definition:
		Use my-api:latest image
		Give it 512 MB RAM
		Open port 8080
	Service:
		“Run 4 copies of this API.”

	Tasks:
		ECS launches:
		Task #1
		Task #2
		Task #3
		Task #4

	If Task #2 dies, the service immediately starts Task #5 to replace it.


Fargate
	Fargate is the compute power (the machines) that actually run your containers
	You never have to set up, update, patch, or scale those machines. - AWS just runs the containers for you
	
	
EC2
	Alternative to Fargate.
	More manual work required of developer
	
	
EKS
	AWS' own simple version of Kubernetes
