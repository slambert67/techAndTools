
Lambda Functions
================
An AWS Lambda function is a piece of code that runs in the cloud without you managing any servers.
You write the code → upload it → AWS runs it automatically when something triggers it.



docker notes
============
When deploying to AWS:		docker build → to build your container images
							Push the image to AWS ECR
							ECS → to run your containers in the cloud
							





2. Tag & push your Docker image to ECR
======================================


# Log in to ECR
works because of aws configure - don't need to specify my credentials
aws ecr get-login-password --region eu-north-1 | docker login --username AWS --password-stdin 869036203214.dkr.ecr.eu-north-1.amazonaws.com - login succeeded


# Build your Docker image (if not done already)
docker build -t my-first-aws-app -f apps/aws/Dockerfile . - done

# Tag the image for ECR
docker tag my-first-aws-app:latest 869036203214.dkr.ecr.eu-north-1.amazonaws.com/my-first-aws-app:latest - done


# Push the image
docker push 869036203214.dkr.ecr.eu-north-1.amazonaws.com/my-first-aws-app:latest - done

Container port

Definition: The port inside the Docker container that your application listens on.

Example: In your Dockerfile/NestJS app, you exposed port 3009:

app.listen(3009);


So your container port = 3009.

ECS/Fargate needs to know this so it can route traffic correctly inside the container.


Container port = port your app listens to inside the container (Dockerfile / app code). see main.ts

Port mapping = how the container port is exposed to the outside world (host / task ENI / load balancer)

For a simple single-container test, just set both to 3009 TCP, no need for fancy networking yet.
