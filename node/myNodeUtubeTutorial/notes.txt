modules - ES
	Javascript now has a module system as part of the language itself - ES Modules or ESM
	file extension is .mjs
	uses import and export

	export patterns
		default exports
			const add = (a,b) => {return a+b}
			export default add;
			import add from './math.js'

			export default (a,b) => {return a+b}
			import add from './math.js'

			const add = (a,b) => {return a+b}
			const sub = (a,b) => {return a-b}
			export default {
				add:add,
				sub:sub
			}
			import both from './math.js'

		named exports
			import and export names must match
				export const add = (a,b) => {return a+b}
				export const sub = (a,b) => {return a-b}
				import * as both from './math.js' or import {add, sub} from './math.js' - preferred

Streams
	sequence of data
	process in chunks instead of waiting for entire sequence. e.g. YouTube video
	cannot control rate at which data arrives - so it is buffered for performance
	intentionally small area node maintains at runtime to process stream of data

	Buffer() class available without importing
	buffer.toJSON()
	buffer.toString()
	buffer.write()
	Don't usually work with buffers directly

	Rarely use streams directly.

	Backpressure in Node streams is the mechanism that prevents fast producers from overwhelming slow consumers. Backpressure is how Node says “slow down, I can’t keep up.”
	Example:
		File stream reads from disk (fast)
		Network stream writes to client (slow)
		Without backpressure:
			Data piles up in memory
			Memory usage grows unbounded
		Backpressure is built into Node’s stream API. You rarely implement it manually — you cooperate with it.
		.pipe():
			wires up backpressure correctly
			pauses and resumes the readable
			prevents memory explosions
			This is why you should almost always use pipe() instead of manual loops.

		fs has stream functionality

		const readableStream = fs.createReadStream('./src.txt', {
			encoding: 'utf-8',
			highWaterMark: 2	// chunk size of 2 bytes
		});

		const writeableStream = fs.createWriteStream('./dest.txt', {
			encoding: 'utf-8',
		});

		// define event handlers
		readableStream.on('data', (chunk) => {writeableStream.write(chunk)});

		4 types of streams
			readableStream
			writeableStream
			Duplex for both read and write e.g. sockets
			Transform streams. Modify data as it is read and written e,g, file compression

pipes
	read and write is a common pattern so replace with pipes
	connects a readable stream to a writable stream
	replace event handler above:
		readableStream.pipe(writeableStream);
	returns destination stream enabling chaining

	chaining

		const gzip = zlib.createCzip();	// transform stream
		readableStream.pipe(gZIP).pipe( fs.writeableStream('file2.txt.gz'));

http
	allows creation of web servers

	const server = http.createServer( (req, res) => {				// callback executed whenever a request reaches the server
		res.writeHead(200, {"Content-Type": "text/plain"})			// success

	// tell server to listen to incoming requests

Event loop

	Primary Queue - part of libub
		timer Queue								Priority 3 - then Microtask Queue
			setTimeout callbacks
			setInterval callbacks
		i/o Queue								Priority 4 - then Microtask Queue
			i/o callbacks - fs, http

		promise queue
			promise callbacks					Priority 2
